What you will be able to do at the end

The goal is not syntax recall. The goal is that this sentence becomes fully transparent to you — every noun in it, and every arrow between the nouns:

The target sentence

“This Terraform module creates an ADLS Gen2 storage account, configures its networking, creates the required containers, assigns a managed identity the appropriate RBAC roles, stores configuration in Key Vault, and exposes outputs consumed by the Databricks module. Terraform tracks those resources in remote state and the CI/CD pipeline generates a plan before applying changes.”

Concretely, you should be able to:

  • Read an unfamiliar Terraform repository and describe its architecture, module boundaries and state layout without running anything.
  • Write Azure infrastructure that follows current provider syntax, uses managed identities instead of keys, and separates environments cleanly.
  • Modify existing configuration and predict what the plan will say before you run it — in particular, whether a change is an in-place update or a destroy-and-recreate.
  • Debug drift, failed applies, state mismatches, dependency cycles and provider errors.
  • Review someone else's Terraform pull request and spot the security and blast-radius problems.

Tooling you will want

You can read the entire course without installing anything. To do the Level 2 exercises you need a terminal, and to do the Azure exercises you need a subscription — the free tier plus a Standard_LRS storage account costs cents, but Databricks and private endpoints are not free, so read those lessons before you apply them.

ComponentVersion used in this courseWhy it matters
Terraform CLI 1.16.x Needs to be ≥ 1.5 for import blocks, ≥ 1.6 for terraform test, ≥ 1.7 for removed blocks. All three are used later in the course.
hashicorp/azurerm ~> 5.0 (5.4.0 current) The Azure provider. Version 5 renamed several arguments you will see in every older blog post — the course flags each one.
hashicorp/azuread ~> 3.0 Entra ID objects (app registrations, groups). Separate from azurerm because Entra ID is not an ARM resource provider.
databricks/databricks ~> 1.0 Everything inside a Databricks workspace. Lesson 12 explains exactly where azurerm stops and this begins.
Azure CLI az 2.x Used for local authentication (az login) and for inspecting what Terraform created.
⚠ Version note — this is the single biggest trap for a new learner

Almost every Terraform-on-Azure tutorial you will find online targets azurerm v3 or v4. The v5 provider (released 2026) renamed or removed arguments those tutorials use. Copying them produces confusing errors like An argument named "enable_rbac_authorization" is not expected here.

This course teaches v5 syntax and marks every changed argument with a version callout, so you can also read v3/v4 repositories at work and know what you are looking at.

The running example

One fictional company carries through the whole course, so that resources can genuinely reference each other rather than being disconnected snippets. From Lesson 5 onward you are building Contoso Analytics' data platform: a medallion data lake, secured with private networking and managed identities, consumed by Databricks and Azure Functions.

Naming follows the widely used Azure convention <type>-<workload>-<env>-<region>-<instance> — for example rg-analytics-dev-weu-01. Lesson 5 explains why storage accounts are the one resource that cannot follow it.

Cost warning

The capstone architecture is not free. Private endpoints bill per hour per endpoint, and a Databricks workspace bills for its compute. If you apply it, apply it to a dev subscription and run terraform destroy the same day. Lesson 20 includes a cost-reduced variant that skips private endpoints so you can complete the exercise cheaply.
